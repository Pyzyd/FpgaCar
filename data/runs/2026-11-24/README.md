## 报文格式（每约 300 ms 一对）

第一行 `D=` `T=` `P=` `O=` `M=`；第二行 `L=` `R=` `VL=` `VR=` `X=` `C=` `DL=` `DR=` `W=` `S=`。
解析细则：

- `L=` / `R=`：8 位十六进制，32 位有符号累计里程计数（每毫米 2532/212 = 11.943 计数）。
- `VL=` / `VR=`：4 位十六进制，16 位有符号，**50 ms 窗口值却按 300 ms 报文发出**，存在采样混叠，不要用来算车速。
- `DL=` / `DR=`：3 位十六进制，速度环之后的最终占空比（0..1200）。
- `C=`：**十进制带符号三位**（如 `-140`、`+103`），不是十六进制。
- `T=` / `X=`：8 路探头位图与其反码，必须严格互补。
- 每个逻辑帧由 4~5 行重复组成，**必须先按时间聚簇（阈值 0.02 s）取簇末行**，否则统计会被重复行带偏。

## 这三次跑出来的关键结论

1. **报文周期实为约 300 ms**（由 `src/uart_report.v:213` 的超声 `dist_valid` 触发），不是注释写的 60 ms。
2. **85% 的循迹帧只压到 1 路探头**：探头间距 11 mm、线半宽 6.5 mm，几何决定「内侧两路同时压线」的窗口只有 2 mm。奇数 `pos` 占 89%，相邻探头切换一次 `Δpos=±2`。
3. **v1.18 期间速度环从未生效**：`cmd_diff=|2C|` 中位 476（run1）/280（run2），而门控 `SYNC_DIFF_MAX=120`，run1 命中 0/173、run2 命中 0/80。
4. **积分权限只有 20**（`I_LIMIT=640 >> I_SHIFT=5`），远小于实测直行所需补偿约 147，导致车靠「主动偏一格」凑，`C` 每帧在 −140 与 +100 之间跳。
5. **v1.19 把静态偏转从 −140 翻到 +103**：TRIM=-140 方向反了（run3 `C` 中位 +103），但抖动明显下降（`|C|>=480` 从 5%/9% 降到 2%，`|C|<=200` 占 73%）。
6. **「右轮恒定只有左轮 0.55」站不住**：稳态帧回归给出 `K_R/K_L` = 0.257（run1）、0.767（run2）、1.013（run3），不单调。TRIM 不能靠一次标定定死。
7. **左右映射没有接反**：`corr(DL−DR, |dL|−|dR|)` = +0.416 / +0.572 / +0.678，三轮均为正。
8. `W=`（宽黑）三轮全程为 0 → `WIDE_CNT_TH=5` 在真实赛道上永不触发，拐角 `wide` 兜底路径形同不存在。
