# K1 倒车入库测试

独立 Ti60 工程。把车摆在入库转向点，短按 K1 开始，K2 随时撤掉驱动。按 K2 或故障停车后，重新摆车，再按 K1 可以重试。

1. 等 2 秒，右轮短刹，左轮向后驱动，车头左转。按 164 mm 轮距、212 mm 轮周长和 2532 计数/圈换算，90° 对应左右轮差约 3077 个计数。按实车约 4° 的余转，`ENTRY_BRAKE_LEAD_DEG` 取 4，在约 2940 个计数时短刹。
2. 短刹 150 ms，两轮直着倒车。领先约 12 mm 的车轮短刹，等落后轮追到约 6 mm 以内再一起倒。两轮各达到 3583 个计数（约 30 cm）后停车。
3. 短刹后留 150 ms 给车停稳，再计时 5 秒。
4. 直着前进，前部八路探头离开起始黑线后开始等待新线。压到主线并确认后短刹，右轮保持短刹，左轮向前驱动。右转 75° 后才允许确认居中的线，105° 内未接到线则停车。
5. 居中压线后交给低速循迹。丢线超过 180 ms 后停车。

转向、直行和倒车的基准占空比为 25%。入库单左轮转向时，若 180 ms 内左轮沿指令方向的净进度不足 8 个计数，则左轮升至 30%，右轮保持短刹。左轮从最近进度基准沿指令方向累计 24 个净计数后回到 25%。无有效进度达到 800 ms 时按故障停车，达到转向目标时立即短刹。倒车追平时落后轮最多给 30%，直行出库的纠偏范围为 22%～28%。循迹基准为 20%，单轮最高 25%。上电等待 K1。先架空核对单左轮的转向，再落地测停车角度和距离。

## 接线与调试

沿用主工程的 Ti60 引脚。当前底盘实测编码器接线为右通道接实际左轮、左通道接实际右轮，两轮原始计数均为前进负计数。测试工程内部进行交换和取向，串口 `L/R` 对应实际左右轮且前进为正。电机 A/B 路和方向沿用主分支的后移底盘配置。

CH340 串口使用 115200 8N1。 `M` 表示当前步骤，`O=1` 表示因方向、编码器、偏差或找线超限停车。 `DL/DR` 是实际左右轮占空比，分母为 1200。

倒车故障会同时记录在 `S`。`S=1` 表示轮子向前累计了过多计数，`S=2` 表示有驱动命令的轮子在 800 ms 内缺少净进度，`S=3` 表示倒车超过 8 秒或两轮行程相差超过约 50 mm。

| M | 步骤 |
| --- | --- |
| 00 | 待机或停止 |
| 01 | 等待 2 秒 |
| 02 | 入库转向及短刹 |
| 03 | 倒车 |
| 04 | 停车计时 |
| 05 | 直行出库及压线短刹 |
| 06 | 右转接线 |
| 07 | 循迹 |

## OV5640 库口停车位置标定

这次用后摄侧装相册的 18 张 1280×720 原图。坐标原点在画面左上角，L 和 R 按画面左右排列。角点取长黑胶带与两条侧边胶带中心线的交点，M 是两角像素坐标的平均值。图里斜穿长边的地砖缝不参与计算。

| 原图 | 左角 L | 右角 R | 中点 M | 单帧判定 |
| --- | --- | --- | --- | --- |
| 08 | (100, 502) | (1196, 610) | (648, 556) | 居中参考 |
| 09 | (108, 505) | (1205, 605) | (656.5, 555) | 居中 |
| 10 | (70, 519) | (1168, 631) | (619, 575) | 居中 |
| 11 | (130, 519) | (1222, 625) | (676, 572) | 偏右 |
| 18 | (170, 342) | (1252, 399) | (711, 370.5) | 右角贴边且高度不同 |

首版触发窗口以 720p 画面中心 `x=640` 为基准。中点进入 `x=616…664`，同时两角离各自画面边缘至少 32 像素、横向间距为 980…1160 像素、中点高度为 `y=530…605`、右角比左角低 70…145 像素，才记为一帧居中。两角必须属于同一条长黑胶带。硬件可以用 `1232 <= xL+xR <= 1328` 直接比较，保留半像素精度。

车上先由停车请求打开找库窗口。低速通过时连续 3 张有效的**相机帧**满足条件，才锁存一次停车触发。漏角、贴边、几何超限或偏出窗口时清空连续帧计数。现有照片是离线单帧样本。实际接入前应从低速移动复测确认触发后停车的位置，再按实际制动位移校正中心值。

320×180 取景区的窗口为 `x=154…166`，中心在 `x=160`。若把点画在 320×240 的 ST7789 屏上，纵坐标按原图除以 4 后再加 30 像素上边距。更换镜头位置、方向、分辨率或裁剪后需要重标。

使用 Python 和 Pillow 重放人工标注与单帧判据，生成参考图、相册总图和 CSV。脚本使用标注坐标，自动提取角点待接入 Ti60。

```powershell
python bench/reverse-parking/mark_garage.py <原始相册目录> <输出目录>
```

## 行进找库调试

打开本分支根目录的 `FpgaCar.xml` 编译整车版。普通循迹和出库恢复循迹都按原来的双轮 PWM 输出乘 70%。调试开关 `PARKING_DEBUG=1` 时超声触发脚保持低电平，K230 可拔掉。

1. 等 ST7789 显示画面，把车摆在线上，再按 K1。每次启动视为收到一次 P，两轮 PWM 从起步开始取各自调速后循迹输出的 80%，约为原输出的 56%。
2. 检出任一有效侧边角点时，两轮 PWM 分别切到各自调速后循迹输出的 60%，约为原输出的 42%。轻微扭动使角点暂时消失时，仍保持这档速度。
3. 角点从 720p 缩采成独立的 320×180 灰度帧，用附近明暗差寻找黑胶带的横边和粗侧边。判断两角属于同一条边时，还会在四分之一、中点和四分之三处检查胶带连续性。
4. 两角通过几何检查、其图像中点连续 2 个检测帧在 `x=616…664` 时短刹 150 ms，再交给自动入库模块。模块等待 2 秒后，锁住右轮、左轮向后转，完成约 90° 转向后双轮直倒 30 cm。停稳 5 秒后直行出库，前探头压线再右转，稳定居中时把电机交回原循迹。本轮只执行一次自动入库。K2 全程可随时停车。

新相册中的双角高度和倾斜与旧相册有明显差异，行进版允许 720p 中点高度约 356–606 像素、右角相对左角约 −32 至 148 像素。双角的横向间距仍为 980–1160 像素。对比度阈值在 `src/garage_corner_scan.v`，中点阈值在 `src/parking_approach.v`。

小屏上两条绿线标出停车窗口。上、下状态条的黄条表示看到单角后切到找库慢速，青条表示已找到双角，红条表示刹车、等待或停车，蓝条表示正在执行入库或出库动作，绿条表示已恢复循迹。UART 仍以 115200 输出，`DL/DR` 可核对实际 PWM。电机交给入库模块后，`M` 按前文动作表显示。当前停车调试版的 `O=1` 表示入库动作判定故障，倒车段的 `S` 给出故障类别。

ST7789 沿用同学的 6 MHz SPI 配置。320×240 全屏的传输加帧间等待约 0.31 秒，取景约 3.2 帧/秒。角点检测使用独立帧缓冲，按相机检测帧确认停车。

### 在 Efinity 手动调 P、D

1. 在 Efinity 打开本分支根目录下的 `FpgaCar.xml`。
2. 双击 Design Files 下的 `src/FpgaCar.v`，搜索 `手动调参区`。P 改 `TRACK_P_GAIN`（当前 80），D 改 `TRACK_D_GAIN`（当前 30）。同一处的三个 `PERCENT` 参数用 0～100 的整数填写。
3. 保存源文件并运行编译。编译结束后在 Efinity Programmer 选择本工程 `outflow/FpgaCar.bit`（JTAG 临时下载）或 `outflow/FpgaCar.hex`（Flash）。
