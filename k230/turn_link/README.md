# K230 → Ti60 转弯通信台架验证

这套程序检验两块实体板能否传方向。K230 保留已测过的箭头判定；发送 500 ms 心跳，以及每次新确认的左转或右转。Ti60 台架工程只接收和显示，不运行整车控制，电机使能、PWM、方向脚都固定为低。

2026-11-18：用户确认左右转方向已在两板上完成初步联调。当前状态是台架方向通过，整车分岔转向尚未验证。`main` 的整车工程仍默认 `USE_K230=0`。

## 先测电平，再接线

解压，把 `turn_verify` 整个文件夹复制到 K230 的 `CanMV → sdcard`。保留 `boot.py`、`ybUtils`、采样程序及原有 `main.py`。`field_turn.py` 仍可单独运行识别；`turn_with_ti60.py` 才会打开通信。

先断开 K230 到 Ti60 的四根信号线，只给 K230 上电。用 CanMV IDE 运行 `turn_verify/measure_gpio.py`，四个信号脚会持续输出高电平 45 秒，结束后拉低。万用表直流挡，黑笔接 K230 排针 **Pin 4（GND）**，红笔逐个测 **Pin 1、2、8、10**。

Ti60 底板 P4 信号侧是 3.3 V。如果 K230 四路实测高电平是 3.3 V，可以依下表连接；若是 1.8 V，在线上加 1.8 V → 3.3 V 电平转换后再接。引脚编号不变。接线时两板先断电，电源各自供给，只接信号和共地。

| 信号 | K230 GPIO | K230 排针 Pin | Ti60 P4 Pin |
|---|---:|---:|---:|
| D0 | 42 | 1 | 28 |
| D1 | 43 | 2 | 33 |
| D2 | 34 | 8 | 34 |
| STB | 35 | 10 | 39 |
| GND | — | 4 | 30 |

## 验证 Ti60 确实收到了方向

1. Ti60 用 `ti60/TurnLinkBench.bit` 做 **JTAG 临时下载到 FPGA**，不要写入 SPI Flash。这个位流与现用整车工程分开，断电重上后恢复原已固化程序。若要重编译，可用同目录的 `TurnLinkBench.xml`。
2. 初测让电机侧保持断电。K230 用 CanMV IDE 运行 `turn_verify/turn_with_ti60.py`，几秒内看 Ti60 的 `LED[0]`。先验空闲心跳，再拿左、右牌各试一遍；两块之间移出画面约一秒。若 GPIO 被其他外设复用，K230 会拒绝发送并在串口给出对应引脚。
3. 停止 K230 通信脚本，约 2 秒后 `LED[0]` 应熄灭；方向灯保留最后一次接收记录。复位 Ti60 可以清除方向和出错记录。

| Ti60 灯 | 台架含义 |
|---|---|
| `LED[5]` | 慢闪，Ti60 本地程序运行 |
| `LED[0]` | 亮 = 接收端见到了链路活动；停发送后约 2 秒熄灭 |
| `LED[1]` / `LED[2]` | 最近收到左转 / 右转，两灯只亮其中之一 |
| `LED[4]` | 每收一次方向就翻转一次；同一牌保持不动时不应反复翻转 |
| `LED[3]` | 亮 = 接收端记过协议错误，复位清除，正常测试应灭 |

K230 屏幕上的「已发」只表示 K230 驱动过引脚。链路没有 ACK，因此用 Ti60 的方向灯与事件灯确认接收。两板通过之后，若要 K230 开机自动运行通信版，先备份当前 `/sdcard/main.py`，再将包里的 `startup_link.py` 改名为 `main.py` 放到 SD 卡根目录。恢复现场连拍时，用 `k230/field_capture/startup_example.py` 作为 SD 卡根目录的 `main.py`。

Git 仓库只保留源码。重建接收测试位流时，在仓库根目录运行 `python k230/turn_link/ti60/make_project.py .scratch/turn_link_bench`，用 Efinity 打开生成的 `TurnLinkBench.xml` 并编译。

工作区验证：`python k230/turn_link/check_turn_link.py --iverilog-dir <bin>` 已回放实际 K230 发送代码产生的电平变化，用仓库的同一份 `src/k230_link.v` 检验心跳、左右转、掉线、方向事件次数以及电机输出。Efinity 2026.1 已完成综合、接口检查、布局布线和生成位流。两板实测状态见本文开头。
