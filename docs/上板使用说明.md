# 上板使用说明（精简版）

K1/K2 按键版的日常操作和 OLED 状态见 [小车使用说明](小车使用说明.md)。本文是上板调试与回归的完整说明。

> 只写「怎么用、看到什么算通过」。设计原理与踩坑记录在 [PROJECT_PLAN.md](../PROJECT_PLAN.md)。
> 每次改代码后同步更新本文；版本记录只记相对上一版的变化。

- 当前版本：**v1.12**（2026-11-23）
- 对应位流：`outflow/FpgaCar.bit`（K230 启用 / ST7789 预览 / 五段弧绕障 / 速度环 / 基础占空比 480 / OLED 三行文字）
- 适用硬件：Ti60 + 电源模块 + TB6612 + YB-MUX04 + HC-SR04 + OLED + K230 + ST7789 彩屏（编码器可选）

## 0. 三分钟速通

```
cd FpgaCar
tools/flash.bat                             # 固化进 Flash（掉电保留），等 FLASH DONE
bash .scratch/prog.sh                       # 只烧 RAM（掉电即丢），调试时用这个更快
powershell -NoProfile -ExecutionPolicy Bypass -File .scratch/rawcap.ps1 -Port COM12 -Ms 3000
```

看到第二行 **77 个可见字符**（含 `W=0 S=0`）、`X=` 与 `T=` 逐位互补 —— 就可以开始测了。
判据见第 4 节，异常见第 5 节。

## 1. 编译、烧录、回归

| 动作 | 命令 | 通过标志 |
|---|---|---|
| 编译 | `cd FpgaCar` 后依次 `C:/Efinity/2026.1/bin/efx_run.bat --flow map FpgaCar.xml`、`--flow pnr`、`--flow pgm` | 日志出现 `Stage completed: pgm` |
| 烧到板子（掉电即丢） | `bash .scratch/prog.sh` | `Device ID read from JTAG: 0x10660A79` + `PROGRAMMING DONE` |
| 固化进 Flash（掉电保留） | `tools/flash.bat` | `Flash verify successful`（只看退出码不算） |
| 全量回归 | `bash tools/run_regression.sh` | 「全部通过」，当前 26 个 tb |

**烧完先验长度**：串口第二行应为 **77 个可见字符**（不含 CR LF；含换行是 79 字节）。37 = v0，69 = v1.0/v1.1，73 = v1.2/v1.3 —— 都没有 `S=`，重烧。

`tools/flash.bat` 三步走：装 JTAG-SPI 桥镜像 `u10660A79.bit` → 写 `outflow/FpgaCar.hex` 并**回读校验** → 回烧 `outflow/FpgaCar.bit` 让应用立即生效。
**不要**用 `--jtag_bridge_mode erase_and_write`，那条分支在校验方法上写死 `none`，零校验也会返 0。

> 烧录的完整说明（含驱动不对时的备用路径 `tools/flash_hiftdi.sh`、故障排查表、换电脑要改什么）见 [`docs/Flash烧录说明.md`](Flash烧录说明.md)。

## 2. 串口怎么看

115200 / 8 / N / 1，CH340 通常枚举为 COM12。每 60 ms 两行（第一行 35 字节 + 第二行 79 字节 = 114 字节，10 位/字节共约 9.9 ms，占不满一帧）：

```
D=015cm T=00011000 P=+00 O=0 M=00
L=00000000 R=00000000 VL=0000 VR=0000 X=11100111 C=+000 DL=1E0 DR=1E0 W=0 S=0
```

| 字段 | 含义 | 判读要点 |
|---|---|---|
| `D=xxxcm` | 超声距离，`---` = 无回波 | 静置小幅抖动正常；大面积 `---` 才算故障 |
| `T=` | 循迹压线位图，**首字符是 bit7（最右）** | 1 = 压线。全 1 或全 0 都要查 |
| `P=±nn` | 线位置 -16..+16，正 = 线在右 | 应与 T 的亮位中心大致对应 |
| `O=` | 障碍标志（当前只看超声 ≤25 cm；红外已拆） | 1 = 触发避障/停车，见第 4 节 |
| `M=nn` | 00 IDLE / 01 RUN / 02 LOST / 03 SEARCH / 04 STOP / 05 后退 / 06 转身 / 07 试探 | 见第 4、5 节 |
| `L=/R=` | 编码器累计里程，32 位二补码**十六进制** | 未装编码器恒 0；装了可用它标定每米脉冲数 |
| `VL=/VR=` | 速度，每 50 ms 窗口净步数，16 位二补码十六进制 | 未装编码器恒 0；速度环靠它工作 |
| `X=` | 消抖后**原始电平**，bit7..bit0 = X8..X1 | **必须与 T 逐位互补** |
| `C=±nnn` | PID 修正量，限幅 **±480**（= `BASE_DUTY`） | 车未进 RUN 时恒 0 属正常 |
| `DL=/DR=` | 实际下发占空比，3 位十六进制 | 直行约 `1E0`(=480)。**这是速度环之后的最终值**（整形器 v1.14 起直通），见下方说明 |
| `W=` | 宽黑标志（影子 / 整片黑） | 1 = 这一拍压线数 ≥5，位置不采信，保持上一拍 |
| `S=` | 最近一次转向方向：0 无 / 1 左 / 2 右 | 找线时能一眼看出往哪边转；保持 1.5 s 后自动回 0 |

**最关键一条**：`X=` 与 `T=` 逐位取反。例：`X=11100111` ↔ `T=00011000`。两者相同即为 `ACTIVE_HIGH` 设反。

**`DL/DR` 不再恒等于 `480±C`**（v1.12 起）：状态机给出 `ctrl_duty` 后还要过 `speed_pid` 做左右轮同步，最多再叠 ±180（`SYNC_MAX`）。
所以「`DL/DR` 与 `480±C` 对不上」有**三个**正常来源：速度环同步修正、状态机改写（LOST 保持 / SEARCH / TURN / 避障分段）、以及编码器失效后的直通。（差速整形在 v1.13 曾是一级，v1.14 起默认直通，不再造成偏差。）
判断当前是哪种，看 `M=` 和 `VL=/VR=`：`VL=VR=0` 说明编码器没脉冲，速度环已经自动直通，此时的 `DL=480+C`、`DR=480-C`。

**差速整形从 v1.14 起默认关闭**（`DUTY_SHAPE_EN=0`，整级直通）。v1.13 曾把差速压一半（`960/0 → 720/240`），
想用「减小动作幅度」治甩尾；闭环仿真推翻了它：压一半等于把可用转向曲率也压一半，最小转弯半径从 80 mm 变成 160 mm，
在 R≤175 mm 的弯上反而直接冲出去（24 组半径×车速里 8 组失败，平均横向误差 68.4 mm，是直通时的 2.3 倍）。
现在 PID 顶满时串口就是 `DL=3C0 DR=000`，和 v1.12 一致。模块保留在工程里（`src/duty_shaper.v`），
将来若要用它做起转死区补偿，把 `DUTY_SHAPE_EN` 改回 1、`SHAPE_DIFF_SHIFT` 保持 0 即可（`SHAPE_DIFF_SHIFT=1` 那条已被证伪）。

## 3. OLED 屏上看到什么

上电白闪一下再转黑是自检，随后按下面布局显示。**不接串口也能判读。**

调试区是**三行各 16 字符的文本**（v1.12 起，此前是数字串 + 竖条 + 状态号 + 四格）：

| 位置 | 内容 | 说明 |
|---|---|---|
| page 0 左 | 8×8 实心方块 | 固件存活标记，随帧翻转，看不到就是 OLED 链路挂了 |
| page 0 右 | 8×8 叉号 | K230 掉线（2 s 内无合法消息）；K230 正常后自动消失 |
| page 1 | `ST:<状态名> LOST:<0/1>` | 状态名 4 字符：`IDLE` / `RUN ` / `LOST` / `SRCH` / `STOP` / `A-BK` / `A-TN` / `A-PB` |
| page 2~5 | 4 个 32×32 汉字色块 | 红 / 绿 / 蓝 / 黄，本轮颜色登记顺序（细则要求必须占 page 2~5） |
| page 6 | `DIST:<三位> CM OB:<0/1>` | 超声距离；无回波显示 `---`，超 999 饱和到 999 |
| page 7 | `LN:<8 位> TR:<L/R/->` | `LN` 自左向右 = line[7]..line[0] = **车体最右到最左**，与串口 `T=` 同序，可逐字对照；`TR` = 最近转向方向 |

`ST:` 显示的是**上报状态**：按 K2 停车时被强制改显 `STOP`，其余情况等于状态机状态 `M=`。
`LOST:` 是丢线标志位，与 `O=`（障碍）分开，一眼能分清「没线」和「被挡」。

调试区三行每次刷新**无条件重写 384 字节**，所以改布局不会留残影。

## 4. 测试流程与通过标准

1. **先架空车轮**（或拔掉电机电源）再上电，串口持续出数 → 链路通。
2. 不压线：`M=00`、`DL=DR=000`、`C=+000` → 起跑安全锁生效（需 K1 按下且压线）。
3. 拿黑线在探头下方来回移：`X=`、`T=`、`P=` 连续变化，屏上 page 7 的 `LN:` 跟随 → 循迹链路通。
4. 车压在线上按 K1：`M` 由 00 转 01，`DL/DR` 离开 000，`C=` 随偏差变化 → PID 在算。
5. 拿起车（丢线）：`M` 依次 01→02→03，`DL/DR` 停在找线占空比 → 状态机正常。
   此时 `S=` 的取值判方向：**先让车压到一片宽黑（手心挡整排，`W=1`）再抬起**，500 ms 内丢线则走拐角兜底——方向取**入弯前最后明确看到的线方位**（`S=1` 线在左 / `S=2` 线在右），从没见过明确方位才回落到 `S=1`；直接抬起来没有宽黑，则按线原来在哪边转。
6. 一直不放回线上：`M` 由 03 走到 **04 STOP**，面板锁停（`SEARCH_FAIL_TO_IDLE=0`）。把车摆回线上再按 K1 继续，不必断电。
7. 手挡在车前 25 cm 内：`O` 转 1，`M` 进避障流程 → 松开后回 01 → 避障链路通。走五段弧时 `M` 在 05/06/07 之间切换，八路离线属预期。
8. 一直挡着不放：走满 3 轮会进 04 停住，此时移开挡板应自动回 01（不用断电）。

**速度环附加验证**（架空车轮，`SPEED_LOOP_EN=1`）：

9. 手拨左右轮，`VL=/``VR=` 应有符号读数；两轮读数明显不等时 `DL/DR` 应反向补偿 —— 快的那侧被压低。
10. 编码器一根线不接满 `NOENC_WIN`(20 窗 × 50 ms = **1 s**) 后自动直通：`VL=VR=0`，`DL/DR` 回到 `480±C`，行为与加环之前完全一致。

本版兜底逻辑：K230 没识别到转向牌时，只要「先宽黑、后丢线」就按**入弯前最后明确看到的线方位**转（线在左就左转、线在右就右转）；只有从没看到过明确方位（刚起步就压上拐角）才用 `DEFAULT_TURN_LEFT=1` 一律左转。普通跑偏仍按「线在哪边往哪边转」找线。
这一条是 v1.14 改的：v1.4~v1.13 是「拐角一律左转」，闭环仿真证明那是 90° 拐角冲出去的主因（126 组入弯位姿里一律左转失败 21 组、按方位转 0 组）。
转向牌走闭环（`TURN_MS=1100` 只作上限），直角约 400~600 ms 就压回线自结束。

## 5. 常见异常速查

| 现象 | 最可能原因 | 处置 |
|---|---|---|
| 串口无任何输出 | 旧位流 / 烧录失败 / CH340 未枚举 | 重跑 `prog.sh`；`Get-PnpDevice -PresentOnly -Class Ports` 查串口是否在线 |
| 第二行只有 37 / 69 / 73 字符 | 板上是 v0~v1.3 旧位流 | 重烧，新位流是 77 字符且带 `W= S=` |
| `D=` 全是 `---` 但探头有回波 | HC-SR04 触发/回响线接反或未共地 | 查 `docs/模块接线说明.md`；仿真侧看 `hc_sr04_tb` |
| 拐角处 `S=` 方向反了 | 入弯前车基本居中线（`P=` 一直 0），`corner_side` 没采到明确方位，回落到 `DEFAULT_TURN_LEFT` | 看丢线前最后几帧 `P=` 的符号；若一直 0，说明车是正中压上拐角的，此时改 `DEFAULT_TURN_LEFT` 或调整入弯位置 |
| 拐角处完全没进兜底、直冲出去 | 没出现宽黑（`W=` 一直 0）或超过 `CORNER_WIDE_MS=500` ms 才丢线 | 确认拐角处 `W=` 出现过 1；宽黑太短可调大 `WIDE_CNT_TH`/`WIDE_MS`（`src/track_line.v:42-43`） |
| `X=` 恒 `11111111`、`T=00000000` | 八路都没看到黑线（不是"全压线"） | 把线摆到探头正下方；仍全 1 就查供电并按 `docs/模块接线说明.md` §2.3 重新校准（本模块无电位器） |
| `W=` 恒 1、`T=11111111` | 影子盖住整排 / 停在深色面 | 抬离桌面；或等 200 ms 后看是否自动转 `M=02` 丢线 |
| 遇障碍后车反复后退转身 | 障碍一直在 25 cm 内 | 正常，走满 3 轮进 04；移开后自动回 01 |
| 绕障后车朝错方向冲 | 绕行结束时车体朝向已变 | v1.6 起不在线上会转 LOST 重新找线；若仍冲，查 `M=` 是否 01 而 `T=` 全 0 |
| 绕障后一路找不到线、最后 STOP | 回线转向不到位 | v1.9 起回线是扫线闭环（`AVOID_TURN_IN_MS=1600` 只作上限，压到线提前结束）。仍找不回说明绕行时车头偏太多，查 `AVOID_PASS_MS` |
| 菱形锐角转弯后丢线 | 牌转向角度不够 | v1.10 起闭环：先转够 250 ms，之后连续 20 ms 压回线就收工；不够就继续加大 `TURN_MS`（闭环会自己提前结束，加大无副作用） |
| `X=` 与 `T=` 相同 | `ACTIVE_HIGH` 极性设反 | 改 `src/track_line.v` 参数 |
| 下地不识别黑线（`X=` 一位不翻） | 模块**未按实际高度校准**（无电位器，靠板上 key1 自动校准） | 上电等 20 s → 长按 key1 至红灯常亮 → 压黑线 3 s 按 key1 → 压白底 3 s 按 key1 → 红灯灭；见 `docs/模块接线说明.md` §2.3 |
| `VL=VR=0` 但车在跑 | 编码器没接 / 没脉冲，速度环自动直通 | 正常。要闭环就查 AB 相接线与共地 |
| `DL/DR` 与 `480±C` 对不上 | 速度环同步修正（±180）/ 状态机改写 / 编码器失效直通 | 看 `M=` 与 `VL=/VR=` 区分，见第 2 节末 |
| 车原地打转不停 | 找不到线，未超 `SEARCH_MS`(1.5 s) | 正常，超时转 04 STOP 锁停 |

**2026-11-25 全域降速 0.8×**：上表占空比全部 ×0.8，`*_MS` 全部 ×1.25，
**切换判据（累计转角 / 里程计数）一个都没动**——它们是几何量，与车速无关。
比例改变的是"走完这段要多久"，不是"走成什么形状"。改其中任何一列时请记住：
两轮**比值**决定弧半径，绝对值只决定快慢；`AVOID_MIN_DUTY=120` 是起转门槛，不随速度缩放。

**v1.21 起这些占空比只是「标称值」**：实际下发值是标称值再叠加航向修正量
`±hdg_steer`（修正量由编码器实测转角与目标角的误差算出），并钳在 `[120, 1200]`。
所以串口看到的 `DL/DR` 会在段内随角度误差变化，不再是一个固定值。
**v1.23 起判据改成「累计转角」（整个绕障过程累积，段间不清零）**：OUT 到 −2133（v1.25 由 −2599 收小）、
ALIGN 回 0、PASS 保持 0、TURN_IN 到 **+1333（v1.24 由 +2334 收小）**、REJOIN 保持
**+500（v1.26 由 +1333 收小，即 15°）** 靠浅角贴线。这样 ALIGN 欠转的角度会自动变成下一段要多转的量，
最终绝对航向由剖面负责，不再逐段丢失误差。
**v1.26 为什么 REJOIN 不再沿用 TURN_IN 的 40°**：v1.22 曾把 REJOIN 目标设成 0（摆平），车平行前进、
永远压不到线，超时后去 S_SEARCH 漫天找线；但一直保持 40° 又会让车以 40° 斜着扎过黑线，交给 track_pid 时
姿态差太大、必然越线再折回。15° 是折中：仍在持续向线收敛，过线姿态接近平行
（仿真交回航向 39.5°→14.6°，越线过冲 57.6→0 mm，下潜深度与最小间隙不变）。
**v1.24 起 PASS / REJOIN 两段另加积分项**（`HDG_I_SHIFT=5`、`HDG_I_LIMIT=320`（2026-11-25 由 400×0.8）、`HDG_STEER_MAX=480`（600×0.8））：
纯 P 环在两轮效率不对称时必须靠一个残留角度偏差才能产生持续差速（实测偏到 50°）；
积分项把这个静差消掉，但**弧线段（OUT/ALIGN/TURN_IN）不用**——加了会逼着车严格走标称几何，
而标称横移 140.9mm 比需要的 142.5mm 少，会擦到方块。

换算公式：`转角(度) = 计数差 × 轮周长 / (每圈计数 × 轮距) × 180/π`。

**【v1.18 实测重标定】上面三个数是量出来的，不是算出来的：**

| 参数 | 旧值（推算） | 实测值 | 怎么测的 |
|---|---|---|---|
| `ENC_CNT_PER_REV` | 3840 | **2532** | 架空车手转左轮 5 圈（右轮全程 0 计数），左轮共 12662 计数 |
| `WHEEL_CIRC_MM` | 232 | **212** | 卡尺量轮径 67~68 mm（取 67.5）× π |
| `WHEEL_BASE_MM` | 160 | 160（未变） | — |

由此每毫米计数 = **11.94**（旧假设 16.55，**高估 39%**）。旧标定的后果：
`ARC_DIFF_TARGET` 按 2772 计数差执行，真实角度是 **83°**（目标 60°，多转 23°）；
`PASS_SUM_TARGET` 按 3310 计数/轮执行，真实距离 **277 mm**（目标 200 mm，多走 77 mm）。

这正是 v1.17 装上编码器后避障反而变差的原因：以前没脉冲，弧线靠 `AVOID_*_MS` 超时
结束（按时长标定，大致对）；一旦有脉冲，里程闭环就按错误的尺子**一直转到够数为止**。

修正后的真值（Verilog 整数运算）：`ARC_CNT_PER_RAD = (2532×160)/212 = 1910`、
`ARC_DIFF_TARGET(60°) = (1047×1910)/1000 = 1999` → 实际 **59.94°**；
`PASS_SUM_TARGET(200 mm) = (200×2532)/212 = 2388` → 实际 **199.9 mm**。

换算表（每毫米 11.94 计数，距离用固件同款整数除法 `mm×2532/212`）：
100 mm → **1194**、150 mm → **1791**、200 mm → **2388**、250 mm → **2985**、300 mm → **3583**；
30° → **1000**、60° → **1999**、90° → **3000**、180° → **6001** 计数差。
现场要反着算：计数差 ÷ 11.94 = 毫米；计数差 ÷ 11.94 ÷ 160 × 57.3 = 度。

**换轮子或换编码器只需改这三个标定参数**（`src/FpgaCar.v:661-663` 例化处，公式会自动跟着变）。

【旧参数为何必须废弃】原来 60° 定长 524 ms，在 v600 < 33 cm/s 时横移不足 14.25 cm，会直接撞上方块 —— 这正是改闭环的直接依据。

【v1.16：没装编码器时，上面三条 ms 就是真实弧长，不是上限】车上目前没有编码器，
`arc_diff` 恒 0，里程闭环永远不触发，于是超时值成为唯一实际时长。v1.13 曾把
`AVOID_OUT_MS`/`AVOID_ALIGN_MS` 当宽松上限调到 2500 ms —— 无编码器下那会让
`BY_OUT` 转 215°、`BY_ALIGN` 只回 18°，车原地转一圈半再跑回起点后方。
现取 `AVOID_OUT_MS=780`、`AVOID_ALIGN_MS=850`、`AVOID_PASS_MS=720`。

为什么要留到 K=0.45 才有余量：占空比到车速的常数 K 在仓库里有两套标定
（duty 600 → 40 cm/s 与 → 30 cm/s，差 50%），而真实车速随电池、地面、轮胎在
**18~46 cm/s** 间漂移，同一段 60° 弧所需时间从 1164 ms 到 436 ms，跨 2.7 倍。
两个方向的代价不对称 —— 转少了会擦方块，转多了还能靠 `BY_TURN_IN` 扫线拉回 ——
所以按慢端偏置，覆盖 27~46 cm/s。

【v1.17：装上编码器后，上表的 ms 会乘以 `AVOID_ENC_MULT=4` 当宽松上限】
上一段的前提是「`arc_diff` 恒 0」。一旦编码器真的送来脉冲，弧线改由里程判据
（60° = 2774 计数差，与车速无关）提前结束，上面三条就退回纯兜底的角色 ——
但车速慢时 60° 弧需要 1160 ms，780 ms 会把它截断。现在 `src/car_fsm.v:256-261`
按「本段是否真收到过脉冲」二选一：收到 → 780×4=3120 ms 上限；没收到 → 原值，
与 v1.16 行为逐位相同。所以**没装编码器时不要把这三条当成上限去调大**，
装了之后也不用改，逻辑自己切换。

**现场判据**：跑一次避障，看绕行是否擦到方块。擦了说明车速比标定更慢，把三条

过宽、车拐出去很远，说明车速更快，按比例缩小。装了编码器后这三条退回上限语义，
无需再调。

> 2026-11-25 全域降速 0.8×：P/D/I 全部 ×0.8（80→64、30→24），`TRIM` 先按 ×0.8 试了 -112。
> 理由：这三者输出的都是**占空比差**，而车画出的曲率 ≈ 占空比差 / 车速；只降 BASE 不降增益，
> 等于把转向放大 25%，弯道会变成"一顿一顿打方向"。若低占空比下发现修正打不动
> （起转死区吃掉差分），把 P/D 往回加（64/24 → 80/30），不要加 BASE_DUTY。

> **2026-11-25 `TRIM` 现场重标：-112 → +34（符号翻转）**
> 自制赛道实测 45 s / 124 帧 RUN：`C=` 时间均值 **+33.6**、`P=` 均值 **+2.37**，
> 两种独立算法一致（`mean(C)`；`TRIM + P_mean×64 = +40`）。稳态下 `corr` 的时间平均
> 必然等于"让两轮等速"所需的物理差速 `c*`，所以 `TRIM` 就该取这个均值。
> 旧值 -140 来自 v1.19「右轮效率只有左轮 0.55」的测量，驱动轮后移到 75 mm、
> 电机通道对调之后该结论已不成立——现在需要**左轮略快**。
> 影响：偏差 146 计数 = 2.3 个 `P` 单位，等于把右侧量程吃到只剩不到 1 个探头，
> 右弯一进就整排丢线（`M=02`），随后 `S_LOST` 保持满舵 + `S_SEARCH` 反向原地转，
> 表现为"从一侧冲出再猛摆到另一侧"。
> **验收标准**：直道 `P=` 均值回到 0±0.5、`C=` 均值 |·|≤10、不再频繁 `M=02`。
> **以后若再改 `BASE_DUTY` 或动机械/接线，这个数必须重新实测**，不能按比例外推。

> **2026-11-25 B 方案（D 低通 + 积分权限写明 + corr 限速）**
> - `D_FILT_SHIFT=2`：D 项不再对量化后的 `pos`（1 格分辨率）直接差分，改成
>   `d_filt += (d_raw - d_filt) >>> 2` 的一阶低通（α=1/4，100 Hz 下约 40 ms 时间常数）。
>   内部按 Q2 定点保存，保证收敛到 0；直接滤整数会卡在 ±1 残差上，留下恒定 `D_GAIN` 偏置。
>   `=0` 即退回旧行为。**代价是 D 的相位超前变小**，所以 `D_GAIN` 可以比原来给得更大再试。
> - `I_LIMIT=192`：积分**真实权限 = 192>>5 = ±6 计数**。这是把"本环实质是 PD + TRIM 前馈"
>   写明：112 计数的轮速差由 TRIM 负责，积分只吸收 1~2 格量化残差。
>   若哪天确实需要积分补 20~40 计数，改 `I_SHIFT`（5→4），不要只把 `I_LIMIT` 放大。
> - `SLEW_STEP=64`：`corr` 每 10 ms 最多变 64 计数，满量程 384 约 60 ms 到顶，
>   压 TB6612 电流尖峰和"甩头"。代价约 1~2 拍滞后；嫌迟钝就 96，嫌甩就 48。
> - 回归：`track_pid_tb` PASS=13（新增"每拍最多 +64"与"12 拍到目标"两条断言，
>   并做过反向验证：把 `SLEW_STEP` 置 0 → `FAIL: slew let corr jump to 504`）。

`TRIM` 是 v1.19 新增的**前馈偏置**，直接叠加在 P/I/D 之上，用来抵消「右轮效率约只有左轮 0.55」造成的静态偏转。上板后调试顺序：直道仍跑偏 → **先只动 TRIM**（步长 ±20）；弯道超调 → 加 `D_GAIN`（24→40）；跟线迟钝 → 加 `P_GAIN`（64→80）。**不要把 `D_GAIN` 拉回 200**，那是拿传感器量化噪声当阻尼。

| `I_SYNC_SHIFT` / `I_SYNC_LIMIT` | `4` / `400` | 积分 1/16、累加钳位（抗饱和） |
| `SYNC_MAX` | `180` | 单次修正上限（15% 占空比） |
| `SYNC_DIFF_MAX` | `120` | 只在两轮指令差 ≤ 120（小差速）时才介入，大差速直通。**v1.19 起整层被 `SPEED_LOOP_EN=0` 关掉，这个门控也一并失效** |
| `NOENC_WIN` | `20` | 连续多少窗口（50 ms/窗）没脉冲就判编码器失效并直通 → 1 s |

编码器失效、两轮反向、或 `en=0`（停机/换相死区/非 RUN）时，速度环**直接直通**并清积分，不会把转向动作改坏。

### 差速整形（`src/duty_shaper.v`）

这一级**从 v1.14 起默认旁路**（`DUTY_SHAPE_EN=0`），保留模块只为将来做起转死区补偿。它当初要解决的问题是：`track_pid` 的 `corr` 限幅正好等于 `BASE_DUTY`，一旦饱和两轮就是 `960/0` —— 内侧轮 0 等于刹车，等效指令是绕车体中心原地转（R = 轮距/2 = 80 mm）。当时以为这「远超赛道弯半径」所以要压小，闭环仿真证明恰恰相反。

整形方式是「只压差速、不动均值」：`mid=(dl+dr)>>1`、`diff=(dl-dr)>>1`，把 `diff` 右移 `DIFF_SHIFT` 位再回代。`DIFF_SHIFT=1` 时 `960/0 → 720/240`，平均仍是 480 —— **但等效转弯半径也从 80 mm 变成 160 mm，可用曲率被砍掉一半**。24 组（R=400/300/250/200/175/160 × 车速 0.35~0.80 mm/s-per-duty）闭环仿真里，`DIFF_SHIFT=1` 有 8 组冲出去、平均横向误差 68.4 mm；`DIFF_SHIFT=0` 0 组失败、平均 14.0 mm。所以 `DIFF_SHIFT` 的正确取值是 0，不是 1。

| 开关 | 位置 | 值 | 作用 |
|---|---|---|---|
| `DUTY_SHAPE_EN` | `src/FpgaCar.v` | `1'b0` | 总开关，0 = 完全直通（v1.14 起的默认） |
| `SHAPE_DIFF_SHIFT` | `src/FpgaCar.v` | `0` | 差速 >> N。**不要设 1 或 2**（见下），0 = 不缩放 |
| `SHAPE_MIN_DUTY` | `src/FpgaCar.v` | `0` | 低占空比地板，救「给了指令却转不动」的半死区。**0 保持 0**，停车不会被顶起来 |
| `SHAPE_SLEW_STEP` | `src/FpgaCar.v` | `0` | 每 ms 最大变化量，消单拍跳变。有相位滞后，默认关 |

`SHAPE_MIN_DUTY` 要靠**实测的电机起转死区**才能定，工程里目前没有这个数据，所以默认必须是 0。架空车轮从 0 慢慢加占空比，看轮子从哪一档开始持续转，那个值再加一点余量填进去。

只在「正在循迹且两轮同向」（`S_RUN` / `S_LOST` 且两轮方向相同）时生效；原地转、找线、避障分段、停车一律直通，语义不变。

**v1.24（2026-11-24）** —— 避障**回线姿态修正**：航向环加积分 + TURN_IN 70°→40° + 清理死代码。**串口字段与长度完全不变**：

- **为什么还要改**：v1.23 实车跑完后反馈「避开障碍物后没有正常找到线，还是垂直赛道走过去」。
  串口数据（`.scratch/run_avoid4.csv`）显示：绕障净转角 **+116.3°**（设计 70°），且 `t=18.40` 时

- **根因一：PASS 段纯 P 环留下稳态差**。620/620 下右轮实测只有左轮的 0.55 倍，纯 P 要产生持续差速
  就必须靠一个**残留角度偏差**：`err>>3` 要累到 ~1656 计数（≈50°）才能给出 ±207 的修正。
  实测 PASS 段航向确实稳在 +50° 偏差上不再回调，TURN_IN 在 +50° 基准上再加 70° → 净 +116°。
  **修法**：给航向环加积分项（`HDG_I_SHIFT=5`、`HDG_I_LIMIT=400`），**只在 PASS 与 REJOIN 两段生效**。
  弧线段不能加：几何仿真里全局加积分会让 KR/KL=0.55 的最小间隙从 100mm 掉到 17mm
  （积分让车严格走标称几何，而标称横移 140.9mm 小于需要的 142.5mm）。
- **根因二：TURN_IN 设成 70° = 几乎垂直撞线**。TURN_IN 的目标角就是车切回原线时的航向角，
  REJOIN 沿用同一目标，所以 70° 意味着以 70°~90° 姿态撞上原线。`src/track_pid.v:8` 的
  `corr = TRIM + pos*P_GAIN + (i_acc>>I_SHIFT) + (pos-pos_d)*D_GAIN` **只有位置误差、没有航向状态**，
  看到线也只能一路歪着修正，压一下就滑出去。**修法**：`AVOID_TURN_IN_ARC_DEG` 70 → 40。
  几何仿真扫角结果：TURN_IN=70° 时过线航向 72°~93°（几乎垂直）；TURN_IN=40° 时六档效率
  （KR/KL 0.50~1.00）全部稳定在 **39.9°±0.4°**，且全部能压到线。而全程最小间隙只由 OUT 弧角决定
  （72.1 / 80.2 / 88.3 / 95.3 / 100.0 / 105.2 mm），**与 TURN_IN 角无关**，所以收小 TURN_IN 不会让车更容易蹭到方块；
  OUT 保持 70°。
- **根因三：几个死参数**。`AVOID_PASS_TRIM`（140）与它生出的 `AVOID_PASS_L_DUTY` / `AVOID_PASS_R_DUTY` 在 v1.21 把 PASS

  （顶层例化里的 `AVOID_PASS_TRIM` 同步删）。

- **v1.24b（2026-11-24 当天追加）**：`AVOID_PASS_MM` 300 → **150**（实车反馈 BY_PASS 直线段太长）。

  KR/KL=0.75 时 88.3 → 79.4 mm；效率更差的几档不变（横移量本就富余）。仍在安全范围内。

  串口 `M=07` 期间的 `DL/DR` 不再出现 PASS 段航向持续偏 +50°（应在 ±10° 内）。

**v1.23（2026-11-24）** —— 避障**定参**：参考角爬坡 + REJOIN 保持斜切 + 弧角 70°。**串口字段与长度完全不变**：

**v1.21（2026-11-24）** —— 避障改**航向闭环**：不再用占空比推算几何。**串口字段与长度完全不变**：

- **根因**：同一对占空比（ALIGN 段 400/840 连发 12 帧）实测轮速比在 **0.66~1.85** 之间乱跳，
  右轮单独在 149~416 mm/s（2.8 倍）之间摆；更关键的是 **duty→速度不单调** —— 右轮
  `duty=760` 实测 383.2 mm/s，反而比 `duty=840` 的 247.8 更快。所以「按占空比算半径」
  这条路在实车上不成立，改多少参数都一样。
- **改法**：把「转角」当被控量。用编码器差算出真实转角 `arc_turn`，与目标角比较，
  误差经死区 + 右移（`HDG_SHIFT=3`）后作为差速修正量叠在标称占空比上：
  `avoid_duty_l = nom_l − hdg_steer`、`avoid_duty_r = nom_r + hdg_steer`。
- **新增参数**：`HDG_SHIFT=3`、`HDG_DEAD=10`、`HDG_STEER_MAX=600`、`HDG_STEER_MIN=60`、
  `AVOID_MIN_DUTY=120`。
- **到位判据带符号**：原来 `arc_diff` 取了绝对值，反方向转同样多也被判「到位」。
  现在 `arc_diff_done = hdg_left_go ? (arc_turn >= +target) : (arc_turn <= −target)`。
- **`avoid_drive` 去掉「占空比严格相等」**：带航向修正后占空比每拍都变，那条判据会让
  `avoid_drive` 抖成 0 → `en` 抖成 0 → 弧线计数全停（状态机卡死）。改为只判方向。
- **单轮占空比下限 120**：TURN_IN 起点误差满量程，不加下限会把内轮压到 45，等于原地打转。
- **PASS 段标称改回对称 620/620**：v1.20 的固定 ±140 偏置会和航向环打架（偏置推着转、
  环往回拉），直线保持交给闭环。`AVOID_PASS_TRIM` 参数保留但不再参与计算。

上板怎么验：每次绕障的**净转角应一致**（设计 +90°，实测 85~95°），不再是 −37°~+103° 乱跳。
OUT 段计数差约 2000、ALIGN 反号约 2000、TURN_IN 约 3000。换段时 `DL/DR` 应随误差变化，
不再是固定的 860/380、400/840。
**v1.20（2026-11-24）** —— 避障三段改闭环：TURN_IN 角度闭环 + PASS 效率补偿 + REJOIN 超时走找线。**串口字段与长度完全不变**：

- **`BY_TURN_IN` 加角度闭环**（`src/car_fsm.v`）。原来这 1600 ms 是纯时间开环，实测拧了 **141°**，
