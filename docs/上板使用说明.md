K1/K2 按键版的日常操作和 OLED 状态见 [小车使用说明](小车使用说明.md)。本文以下内容对应早期循迹调试版。

- 当前版本：**v1.8**（2026-11-19）
- 对应位流：`outflow/FpgaCar.bit`（超声参与避障 / 红外已拆 / 关 K230）
- 适用硬件：Ti60 + 电源模块 + TB6612 + YB-MUX04 + HC-SR04 + OLED，K230 不接

## 0. 三分钟速通

```
cd FpgaCar
bash .scratch/prog.sh                       # 烧位流，等 PROGRAMMING DONE
```

看到第二行 77 个字符（含 `W=0 S=0`）、`X=` 与 `T=` 逐位互补 —— 就可以开始测了。

## 2. 串口怎么看

115200 / 8 / N / 1，CH340 通常枚举为 COM12。每 60 ms 两行：

```
D=015cm T=00011000 P=+00 O=0 M=00
L=00000000 R=00000000 VL=0000 VR=0000 X=11100111 C=+000 DL=000 DR=000 W=0 S=0
```

| 字段 | 含义 | 判读要点 |
|---|---|---|
| `D=xxxcm` | 超声距离，`---` = 无回波 | 静置小幅抖动正常；大面积 `---` 才算故障 |
| `T=` | 循迹压线位图，**首字符是 bit7（最右）** | 1 = 压线。全 1 或全 0 都要查 |
| `P=±nn` | 线位置 -16..+16，正 = 线在右 | 应与 T 的亮位中心大致对应 |
| `O=` | 障碍标志（当前只看超声 ≤25 cm；红外已拆） | 1 = 触发避障/停车，见第 4 节 |
| `M=nn` | 00 IDLE / 01 RUN / 02 LOST / 03 SEARCH / 04 STOP / 05 后退 / 06 转身 / 07 试探 | 见第 4、5 节 |
| `L=/R=` | 编码器累计 | 未装编码器，恒 0 属正常 |
| `VL=/VR=` | 速度 | 未装编码器，恒 0 属正常 |
| `X=` | 消抖后**原始电平**，bit7..bit0 = X8..X1 | **必须与 T 逐位互补** |
| `C=±nnn` | PID 修正量，限幅 ±600 | 车未进 RUN 时恒 0 属正常 |
| `DL=/DR=` | 实际下发占空比（3 位十六进制） | DL=600+C、DR=600-C，600=0x258 |
| `W=` | 宽黑标志（影子 / 整片黑） | 1 = 这一拍压线数 ≥5，位置不采信，保持上一拍 |
| `S=` | 最近一次转向方向：0 无 / 1 左 / 2 右 | 找线时能一眼看出往哪边转；**没牌时拐角应恒为 1（左）**。保持 1.5 s 后自动回 0 |

**最关键一条**：`X=` 与 `T=` 逐位取反。例：`X=11100111` ↔ `T=00011000`。两者相同即为 `ACTIVE_HIGH` 设反。

## 3. OLED 屏上看到什么

上电白闪一下再转黑是自检，随后显示下面五块。**不接串口也能判读。**

| 位置 | 内容 | 说明 |
|---|---|---|
| page0 中部 | `10000001` 八位二进制串 | 自左向右 = bit7..bit0，与串口 `T=` 字符序一致，可逐字对照 |
| page1 | 八根竖条 | 第 1 根 = X1 = 车体最左；压线那路整列点亮 |
| page6/7 左 | 三位数字 + `cm` | 超声距离；无回波显示 `---`，超 999 饱和 |
| page6/7 中 | 一位状态号 | 与串口 `M=` 同值 |
| page6/7 右 | 四格 | 自左向右：障碍 / 丢线 / **左转** / **右转**；实心 = 置位。左/右红外已拆，原两格改显转向方向 |

中间四个 32×32 汉字色块（红绿蓝黄）是颜色顺序显示区，K230 未接时保持空槽。

## 4. 测试流程与通过标准

1. **先架空车轮**（或拔掉电机电源）再上电，串口持续出数 → 链路通。
2. 不压线：`M=00`、`DL=DR=000`、`C=+000` → 起跑安全锁生效（需连续压线 2 s）。
3. 拿黑线在探头下方来回移：`X=`、`T=`、`P=` 连续变化，屏上 page1 竖条跟随 → 循迹链路通。
4. 车压在线上静置 2 s：`M` 由 00 转 01，`DL/DR` 离开 000，`C=` 随偏差变化 → PID 在算。
5. 拿起车（丢线）：`M` 依次 01→02→03，`DL/DR` 停在找线占空比 → 状态机正常。
   此时 `S=` 的取值判方向：**先让车压到一片宽黑（手心挡整排，`W=1`）再抬起**，2 s 内丢线则 `S=1`（拐角兜底左转）；直接抬起来没有宽黑，则按线原来在哪边转（`S=1` 或 `S=2`）。
6. 一直不放回线上：`M` 由 03 回到 **00**（不是 04）→ 可反复测，不必断电。
7. 手挡在车前 25 cm 内：`O` 转 1，`M` 走 05(后退)→06(转身)→07(试探) → 松开后回 01 → 避障链路通。
8. 一直挡着不放：走满 3 轮会进 04 停住，此时移开挡板应自动回 01（不用断电）。

本版新增**拐角兜底**：K230 没装 / 没识别到转向牌时，只要「先宽黑、后丢线」就一律左转（菱形那两段各触发一次左转）。
注意它不会影响正常跑偏：没有宽黑的普通丢线仍按「线在哪边往哪边转」找线。

上版至今的现场行为变化：找线失败回 IDLE 而非永久停车；**遇障碍不再原地干停，改成后退-转身-试探**。
另外新增宽黑兜底：影子/整片黑不再被当成"完美居中"直冲，而是保持上一拍位置、超 200 ms 降级为丢线。

## 5. 常见异常速查

| 现象 | 最可能原因 | 处置 |
|---|---|---|
| 串口无任何输出 | 旧位流 / 烧录失败 / 只开 Ti60 开关而 USB 未枚举 | 重跑 `prog.sh`；查 `pnputil /enum-devices /connected /class Ports` |
| 第二行只有 37 / 69 / 73 字符 | 板上是 v0~v1.3 旧位流 | 重烧，新位流是 77 字符且带 `W= S=` |
| 拐角处 `S=2` 右转出去 | 没宽黑（线太窄一次只压 2 路）或 `DEFAULT_TURN_LEFT=0` | 确认拐角处 `W=` 出现过 1；必要时抬高 `WIDE_CNT_TH` 前的判断或把兜底方向改右 |
| `X=` 恒 `11111111`、`T=00000000` | 八路都没看到黑线（不是"全压线"） | 把线摆到探头正下方；若确实压在线上仍是全 1，查模块供电，并按 `docs/模块接线说明.md` §2.3 重新按键校准（本模块无电位器） |
| `W=` 恒 1、`T=11111111` | 影子盖住整排 / 停在深色面 | 抬离桌面；或等 200 ms 后看是否自动转 `M=02` 丢线 |
| 遇障碍后车反复后退转身 | 障碍一直在 25 cm 内 | 正常，走满 3 轮进 04；移开后自动回 01 |
| 丢线滑行中撞到东西 | v1.6 前的位流只在 RUN 判障碍，LOST 会盲目前进 300 ms | v1.6 起 LOST/SEARCH 期间也会转避障；换位流 |
| 绕障后车朝错方向冲 | 绕行结束时车体朝向已变，但旧代码直接回 RUN | v1.6 起不在线上会转 LOST 重新找线；若仍冲，查 `M=` 是否 01 而 `T=` 全 0 |
| `X=` 与 `T=` 相同 | `ACTIVE_HIGH` 极性设反 | 改 `src/track_line.v` 参数 |
| 下地不识别黑线（`X=` 一位不翻） | 模块**未按实际高度校准**（本模块无电位器，靠板上 key1 自动校准） | 上电等 20 s → 长按 key1 至红灯常亮 → 压黑线 3 s 按 key1 → 压白底 3 s 按 key1 → 红灯灭；详见 `docs/模块接线说明.md` §2.3 |
| `D=---` 占比高 | 超量程或反射面太斜 | 属正常，靠近再看 |
| `DL/DR` 恒 000 但 `M=01` | v1.0 位流的 `dead_cnt` 位宽 bug（v1.1 已修） | 换 v1.1 位流；换完仍 000 就对照 `C=` 是否也 0 |
| 车原地打转不停 | 找不到线，未超 `SEARCH_MS`(1.5 s) | 正常，超时会回 IDLE |

## 7. 版本记录

**v1.8（2026-11-19）** —— 第二轮全仓审查后的修复。**报文格式与长度完全不变（第二行仍是 77 字符）**，无新字段：

- 修回归门禁的假绿灯：`ALLPASS=0` 此前被判成通过。历史上 `hc_sr04_period_tb` 报告过「OK / ALLPASS=0 / 0 失败」，实际是漏检。**这条不影响车上行为，但影响你对"回归全绿"的信任。**
- 修转向牌隐患：交通牌强制转向期间车体扫过宽黑会污染拐角记忆，转向结束后丢线时兜底可能把牌的方向**反着执行**。写这条时 `USE_K230=0` 所以不触发；**2026-11-20 起 `USE_K230=1'b1`，这条已经生效**，靠 `car_fsm` 里转向牌强制转向期间屏蔽拐角记忆的改动挡住。
- `track_line` 的 `DEBOUNCE_N` 此前是空参数（固定按 4 拍比较），现真正生效；消抖由「实际 5 拍」修正为「正好 4 拍」。
- 删掉死寄存器 `saw_line`；`oled_driver` 的 `ack_err`/`nack_seen` 补进复位初值。
- 测试设施：`car_fsm_tb` 新增第七个实例覆盖转向牌四条路径；单 tb 超时上限 180 → 420 s；编译警告不再被丢弃（跑完会打印前 12 条）。

**v1.7（2026-11-19）** —— 订正循迹模块的调阈值方式。相对 v1.6 只有文档改动，**无代码、无位流变化**：

- 明确 YB-MUX04 **没有电位器**，阈值靠板上 `key1` 按键自动校准（依据官方说明书与 README）。此前文档里「拧电位器」的说法已全部订正。
- 异常速查新增一行「下地不识别黑线」的处置（本模块最常见原因就是没按实际高度校准）。
- 完整校准步骤见 `docs/模块接线说明.md` §2.3，原理与协议见 `PROJECT_PLAN.md` §3.34。

**v1.6（2026-11-19）** —— 补三处状态机盲区。相对 v1.5 的变化：

- **丢线/找线期间也避障**：`obstacle` 原来只在 `S_RUN` 与试探段检查。丢线后车会按上一刻占空比继续前进 300 ms（约 10 cm），找线时贴着障碍原地转最长 1.5 s —— 这两段时间对障碍是"瞎"的。现在这两段一旦出现障碍立刻转避障。
- **绕障结束不再硬回 RUN**：试探段走完时车体朝向与线的相对关系已经完全变了。旧代码无条件进 RUN，等于拿一份过期的 PID 值瞎跑；现在压在线上才回 RUN，否则交给找线。
- **试探段加 100 ms 静默窗**：从转身进试探时障碍通常还在正前方，旧代码第一拍就判障碍把试探打回，3 轮配额瞬间烧光，避障退化成"原地左右各抖 600 ms 再停车"。现在前 100 ms 不判障碍。
- 转向指示在收到"直行牌"时立即熄灭，不再亮满 1.5 s。
- 串口报文长度不变（仍 77 字符），字段与语义均未变。

**v1.5（2026-11-19）** —— OLED 四标志格改显转向方向；转向指示加保持计时。相对 v1.4 的变化：

- **OLED 四标志格改版**：自左向右由「障碍 / 左红外 / 右红外 / 丢线」改为「障碍 / 丢线 / **左转** / **右转**」。左/右红外模块已从车上卸下，原两格改显转向方向（与串口 `S=` 同源）。
- **转向指示加保持**：`turn_dir` 原来置位后永不清零，第一次转弯后 OLED 上那一格会一直亮着 —— 直道上也显示"正在左转"，四格就失去意义了。现在保持 **1500 ms** 后自动熄灭（`TURN_DIR_HOLD_MS`）。保持太短 OLED 每 100 ms 才采一次样抓不到；太长又会常亮，1500 ms 正好覆盖整个 `S_SEARCH`。
- 判读变化：OLED 上左转/右转格表示的是「1.5 s 内转过哪边」，不是"车身此刻正在转"。串口 `S=` 同理。
- 串口报文长度不变（仍 77 字符），`S=` 语义不变，只是会自己归 0。
- **回归脚本修 bug**：`tools/run_regression.sh` 原来用固定的临时文件名，两人同时跑会互相覆盖；且 `grep -c` 在日志缺失时返回空串，脚本把"没跑成"误判成"全部通过"。现在每次运行用独立后缀，所有计数兜底为 0。

**v1.4（2026-11-18）** —— 加拐角兜底（默认左转）。相对 v1.3 的变化：

- 串口第二行 73 → **77 字符**，末尾新增 `S=`（最近一次转向方向：0 无 / 1 左 / 2 右）。只看长度即可区分位流版本。
- 新增**拐角兜底**：宽黑（`W=1`）后 500 ms 内丢线、且没有转向牌事件时，一律左转（`DEFAULT_TURN_LEFT=1`）。这是「没装 K230 / 没识别到牌」时跑菱形赛道的兜底。
- **不影响正常跑偏**：没有宽黑的普通丢线仍按「线在哪边往哪边转」找线 —— 否则正常右弯跑偏会被强制左转，越找越远。

**v1.3（2026-11-18）** —— 修消抖采样单位错，**现场手感会有变化**。相对 v1.2 只有一处改动：

- 消抖节拍由实际 1 µs 改回设计值 **1 ms**（`SAMPLE_KHZ` 由 `1000` 改 `1`）。原来「连续 4 次一致」实际只滤 4 µs，黑白交界的抖动基本没被滤掉；现在要连续 **4 ms** 稳定才认账。
- 现场表现：推线时 `T=`/`P=` 的响应会略微变慢（约 4 ms，肉眼几乎无感），但压在黑白交界处时读数不再乱跳，PID 微分项不会被打出尖峰。
